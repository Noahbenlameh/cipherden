# CIPHERDEN

Портативный, полностью офлайн менеджер паролей и чувствительных данных.
Данные хранятся зашифрованными на съёмном накопителе (SSD/USB); вынули
накопитель — на хост-машине не осталось ничего пригодного к
использованию. Панель управления стремится к повседневной привычности
таблицы, а не к трению традиционной формы менеджера паролей.

*(на ранних этапах разработки назывался «SecureVault» — тот же проект, новое название)*

## Зачем нужен CIPHERDEN, если есть облачные менеджеры паролей

| Без CIPHERDEN | С CIPHERDEN |
|---|---|
| Данные лежат в облаке третьей стороны (менеджер паролей, Google Sheets, заметки) | Всё живёт только на своём накопителе — сервер, которому можно доверять или не доверять, просто отсутствует |
| Приложение слушает сеть, синхронизируется, шлёт телеметрию | Ни одного открытого сетевого порта и ни одного исходящего запроса — десктопный Tauri-шелл, не веб-сервер |
| Один сейф на все данные — украли мастер-пароль, украли всё | Оболочка + независимые разделы (Аккаунты/Файлы/Seed/Ledger), каждый со своим паролем; без пароля оболочки не видно даже, сколько разделов существует |
| Забыл пароль — данные потеряны безвозвратно | Восстановление пароля оболочки через независимый резервный слот |
| Нужно ставить ПО с правами администратора на каждый компьютер | Портативный бинарник прямо на накопителе — подключил, запустил, ничего не остаётся на хосте |
| Перенос из другого хранилища — вручную, руками | Импорт из CSV и KeePass `.kdbx` из коробки |

## С чего начать

| # | Шаг | Что делать |
|---|---|---|
| 1 | Подключите накопитель | SSD/USB с развёрнутым CIPHERDEN (exFAT — читается на Windows/macOS/Linux без драйверов) |
| 2 | Запустите бинарник | Портативный, ничего не устанавливается на хост-машину |
| 3 | Разблокируйте Оболочку | Один пароль — открывает рабочий стол с иконками существующих разделов |
| 4 | Откройте нужный раздел | Клик по иконке → отдельный пароль этого раздела → его содержимое |

## Разделы

| Раздел | Что хранит |
|---|---|
| **Аккаунты** | Логины, пароли, заметки — табличный интерфейс |
| **Файлы** | Зашифрованный файловый сейф — добавление/извлечение через нативные системные диалоги, без монтирования на уровне ОС |
| **Seed** | Seed-фразы криптокошельков, отдельно помеченный и предупреждённый раздел |
| **Ledger** | Учёт баланса/операций, с возможностью вручную датировать запись при импорте старых записей |
| **System** | Только для чтения, без пароля: статус шифрования по каждому разделу, статистика диска/процесса, счётчики неудачных попыток входа |

## Возможности подробнее

> [!TIP]
> **Настоящее скрытие существования.** Без пароля Оболочки атакующий видит один зашифрованный файл с обобщённым именем — не список разделов, не их названия, даже не их количество. Это осознанный выбор вместо более простой схемы «отдельный файл на раздел» — подробности компромисса см. в `THREAT_MODEL.md`.

> [!NOTE]
> **Две темы интерфейса** — Cyberpunk (оригинальная) и Signal (латунь/медь, анимация разблокировки с сетью частиц), переключаются прямо с экрана блокировки.

> [!TIP]
> **Экстренный выход** (кнопка или Ctrl+Shift+X) мгновенно очищает весь ключевой материал из памяти и завершает работу без единого подтверждения — на случай, когда накопитель нужно выдернуть прямо сейчас.

> [!WARNING]
> **Восстановление пароля Оболочки** — это осознанный компромисс: реальная восстанавливаемость на случай забытого пароля ценой отсутствия пути назад, если потеряны сразу оба пароля (основной и резервный). Подробнее — в `THREAT_MODEL.md`.

## Техническая часть

- **KDF**: Argon2id через крейт RustCrypto [`argon2`](https://crates.io/crates/argon2), по умолчанию 256 МиБ / 3 прохода / 4-кратный параллелизм.
- **Хранение**: [SQLCipher](https://www.zetetic.net/sqlcipher/) (AES-256, аутентификация каждой страницы через HMAC) через `rusqlite` — сам зашифрованный файл SQLCipher *и есть* контейнер раздела, включает собственный OpenSSL, поэтому никогда не зависит от того, что установлено на хосте.
- **Оболочка + разделы**: один зашифрованный файл оболочки на диске содержит таблицу разделов, каждый — со своими солью/параметрами KDF и непрозрачным зашифрованным blob. Общая логика создания/открытия/ключевания (`crates/vault-core/src/container.rs`) переиспользуется каждым разделом.
- **Разделы на диске**: отдельные зашифрованные файлы-контейнеры на одном обычном разделе exFAT, не настоящие разделы диска — так подключённый накопитель читается на любой ОС без установки драйверов монтирования.
- **Память**: мастер-пароль никогда не касается диска — только производный ключ, в памяти, в типе, который обнуляется при уничтожении, на странице, заблокированной от выгрузки в swap (`mlock`/`VirtualLock`).
- **Устойчивость к записи**: файлы ключа/метаданных пишутся атомарно (временный файл + `fsync` + переименование) — прерванная запись (накопитель выдернули посреди сохранения) не может их повредить.
- **Импорт/экспорт**: CSV через крейт `csv`; KeePass `.kdbx` через крейт `keepass` — читают/пишут только уже проверенные форматы, без собственного парсинга.
- **Фронтенд**: `dist/` — простой HTML/CSS/JS без сборщика, отдаваемый напрямую Tauri; встраивается прямо в скомпилированный бинарник — тот самый «один портативный файл».

Полная модель угроз (от чего защищает и не защищает) — в [`THREAT_MODEL.md`](THREAT_MODEL.md). Принципы криптографического дизайна и порядок раскрытия уязвимостей — в [`SECURITY.md`](SECURITY.md).

## Статус

MVP полностью готов и работает, проект вырос далеко за исходные рамки:

- [x] `vault-core`: KDF Argon2id + ядро хранения на SQLCipher/AES-256-GCM (создание/открытие/CRUD/поиск/резервное копирование), без UI-зависимостей, 76 тестов.
- [x] Архитектура «Оболочка + разделы»: Аккаунты, Файлы, Seed, Ledger, доступные через рабочий стол с иконками.
- [x] Восстановление пароля Оболочки (основной + резервный слот).
- [x] Две темы интерфейса, список известных хранилищ, нативные системные диалоги выбора файлов/папок.
- [x] System-панель — только для чтения, без пароля.
- [x] Импорт CSV/KeePass `.kdbx`, экспорт выбранных строк в CSV, опциональный экспорт отдельного раздела в самостоятельный файл.
- [x] CI (GitHub Actions): fmt/clippy/сборка/тесты на macOS, Linux, Windows + проверка цепочки поставок (`cargo-audit` + `cargo-deny`).
- [x] Портативный бинарник — запускается самостоятельно из любой директории.
- [x] Кроссплатформенные портативные сборки для macOS, Windows, Linux (GitHub Actions), без установщика и прав администратора.
- [x] Экстренный выход.

Осознанно отложены (не начаты): лаунчер SSH/Tailscale, защита от принуждения на основе скрытого тома, аппаратная 2FA (YubiKey) — см. `THREAT_MODEL.md`.

## Установка

Публичных релизов ещё не было — единственный путь сейчас — собрать из исходников:

```sh
git clone https://github.com/Noahbenlameh/cipherden.git
cd cipherden
cargo build --workspace --release
./target/release/cipherden
```

Запустить тесты:

```sh
cargo test --workspace
```

Портативные сборки под macOS/Windows/Linux также можно получить через workflow `Release builds` в GitHub Actions этого репозитория (вкладка Actions → Run workflow) — результат складывается в артефакты запуска.

## Благодарности

CIPHERDEN не содержит скопированного стороннего исходного кода — только использует опубликованные библиотеки по их собственным лицензиям:

- [`argon2`](https://crates.io/crates/argon2) (RustCrypto) — деривация ключа.
- [SQLCipher](https://www.zetetic.net/sqlcipher/) через [`rusqlite`](https://crates.io/crates/rusqlite) — шифрование хранения.
- [`keepass`](https://crates.io/crates/keepass) — импорт `.kdbx`.
- [`csv`](https://crates.io/crates/csv) — импорт/экспорт CSV.
- [Tauri](https://tauri.app/) — десктопная оболочка приложения.
